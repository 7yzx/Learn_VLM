# 与主流算法逐步对比（DAPO / PPO / GRPO / RLAIF / Agent-RL）

> 本文按“训练流水线步骤”逐步对比：你这个项目在哪里更强、哪里有取舍。

## 0. 对比对象说明

为了更公平，选以下常见路线：
- 经典 PPO-RLHF（InstructGPT/TRL 风格）
- GRPO 类方法（DeepSeek-R1 系列常见）
- RLAIF / LLM-as-a-judge 奖励
- Tool-Agent 训练（Toolformer / ReAct 类思路）
- 通用多模态 SFT 或单阶段 CoT 微调

---

## 1. 数据与提示构造阶段

### 你的做法
- 在样本中携带结构化 bbox 元信息（`x_values_bbox/y_values_bbox`）和 `metadata`；
- prompt 中明确工具可用能力与动作规范（`ACTION 0`、`FINAL ANSWER`）。

### 主流做法
- 多数 RLHF 仅有 `prompt/response/reward`，很少注入可执行视觉结构化元信息；
- 多模态 SFT 常强调“自然语言描述”，不强调程序化工具参数。

### 强项
- 对图表任务信息利用率高，工具调用可直接落到 bbox；
- 行为空间更可控（工具函数签名清晰）。

### 代价
- 对数据预处理质量依赖高（bbox 准确度影响上限）；
- 可迁移到非结构化视觉任务时需要额外适配。

---

## 2. Rollout（采样）阶段

### 你的做法
- 第一次 rollout 生成 action；
- 若有合法工具调用，执行后构造第二次 rollout；
- 最终回答可来自第二轮观察后推理。

### 主流做法
- PPO/GRPO 通常单次 rollout；
- Agent 框架虽支持多轮，但很多训练时并不把“执行结果”真正纳入同一 RL 更新闭环。

### 强项
- 真正实现 Think with Images：行动影响后续观测，观测影响策略更新；
- 对需要局部聚焦的 ChartQA 任务更有效。

### 代价
- 训练时延与工程复杂度更高；
- 需要处理工具失败、格式错误、图像 IO 异常等边界场景。

---

## 3. 工具执行与安全约束阶段

### 你的做法
- 解析器只接受限定形态代码；
- 上下文只暴露白名单工具（`focus_on_*`）；
- 失败路径写入 `penalty` 并追踪错误码。

### 主流做法
- 纯文本 ReAct 多依赖 prompt 约束，运行时约束较弱；
- 一些 agent benchmark 只离线评测，不把错误处理进训练信号。

### 强项
- 训练可控，便于安全上线；
- 错误可以转成学习信号（负奖励）。

### 代价
- 工具空间受限，探索能力不如“开放 Python 执行”。

---

## 4. 奖励阶段

### 你的做法
- 规则奖励（`refocus.py`）可做数值相似度与多答案匹配；
- 可切换 LLM judge（`refocus_llm.py`）；
- 奖励接口统一（batch / llm_batch / llm_double）。

### 主流做法
- 经典 PPO-RLHF 常用 reward model（RM）打分；
- RLAIF 采用 LLM judge，但多在文本任务，视觉工具链结合较少。

### 强项
- 工程灵活：规则法便宜稳定，LLM judge 语义鲁棒；
- 能快速迭代 reward 设计，不改 trainer 主干。

### 代价
- 规则奖励可能与真实用户偏好有 gap；
- LLM judge 引入外部依赖与成本波动。

---

## 5. 优势估计与策略优化阶段

### 你的做法
- 支持 `GAE/GRPO/RLOO/REINFORCE++/REMAX`；
- 默认配置 `adv_estimator: grpo`；
- policy loss 使用 DAPO 风格双侧 clip（`clip_ratio_low/high/dual`）；
- 可选 KL loss + ref policy 约束。

### 主流做法
- 经典 PPO：GAE + value critic；
- 新一代 reasoning RL（如 GRPO）减少对 critic 依赖；
- 很多实现只有单侧 clip 或固定损失模板。

### 强项
- 算法可插拔，适合研究对比；
- DAPO 风格 clip 对大模型策略更新更稳；
- GRPO 与多采样回答天然匹配（`rollout.n > 1`）。

### 代价
- 超参空间更大，调参成本上升；
- 多算法共存增加实现和排障复杂度。

---

## 6. 分布式系统阶段

### 你的做法
- Ray 单控制器 + 角色化 worker；
- FSDP 做训练，vLLM 做推理；
- 支持 offload、rank0_init、sequence parallel。

### 主流做法
- 单机 DDP 或 TRL 小规模训练；
- 训练推理耦合（同一引擎）导致吞吐瓶颈。

### 强项
- 工业级扩展能力更强；
- 训练与 rollout 解耦，综合效率高。

### 代价
- 运维/调度复杂度高于单机方案；
- 需要更严格的环境管理（CUDA/NCCL/Ray/vLLM 兼容）。

---

## 7. 评估与可观测性阶段

### 你的做法
- 记录 `tool_call_ratio`、`tool_call_success_rate`；
- trace 可落盘 tool code、二次提示词、原图/编辑图。

### 主流做法
- 常见只记录 reward/loss，很少记录 agent 行为层指标。

### 强项
- 更容易定位“为什么失败”（不会只看到 reward 降低）；
- 便于做行为对齐（减少无效工具调用）。

---

## 8. 结论：你这个方案的相对位置

## 综合优势
1. **比普通 PPO/GRPO 更 agentic**：行动-观测-再行动的闭环完整。  
2. **比纯 SFT 更可解释**：工具调用与图像变换可审计。  
3. **比单一奖励方案更灵活**：规则奖励与 LLM judge 双轨。  
4. **比轻量 RL 脚手架更工程化**：Ray + FSDP + vLLM 成熟。  

## 主要风险/短板
1. 工具调用策略可能过拟合模板提示；  
2. 二次 rollout 带来额外训练成本；  
3. 外部 LLM 判分存在方差与成本问题；  
4. 需要持续做工具失败鲁棒性治理。

---

## 9. 面试时一句话定位

这是一个 **把 DAPO/GRPO 训练、可执行视觉工具调用、两阶段多模态 rollout** 真正融合在一起的 VeRL 实践：
- 在算法上：兼容主流 RL 优化器并强调稳定更新；
- 在系统上：分布式可扩展；
- 在产品化上：行为可追踪、可解释、可迭代。
